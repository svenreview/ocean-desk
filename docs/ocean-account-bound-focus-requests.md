# Ocean Desk 2.0 — 23차 인증 전환·지연 요청 보호

상태: 개발 브랜치 / Google OAuth 실제 로그인 미연결 / 운영 환경 미적용.

## 위험
로그아웃 또는 계정 A에서 계정 B로 전환하는 중, 이미 출발한 집중 기록 서버 요청의 응답이 뒤늦게 도착할 수 있습니다. 화면과 복구 버튼에 이전 계정의 결과가 표시되거나 잘못된 세션을 이어받으면 안 됩니다.

## 이번 개선
- `od-focus-sync.js`: 현재 인증 계정 ID와 인증 세대 번호를 유지. 출발 전·토큰 획득 후·서버 응답 후 확인해 다른 계정 응답은 무시합니다.
- 사용자 ID가 변경되거나 로그아웃하면 집중 세션 및 복구 후보를 메모리에서 즉시 제거합니다.
- 동일 Google 계정 토큰 자동 갱신은 사용자 ID가 유지되므로 타이머를 끊지 않습니다.
- 계정 전환 후 뒤늦게 도착하는 서버 조회 성공/실패는 새 계정의 복구 상태 표시를 덮어쓰지 못합니다.
- `tests/auth-account.spec.mjs`: 서버 집중 조회 응답을 의도적으로 지연시킨 후 계정을 바꾸는 모의 브라우저 테스트 추가.

## 남은 과제
- 이 방어는 **클라이언트에 이전 계정 세션을 표시하지 않기 위한 조치**입니다. 이미 서버로 전송된 세션 시작/취소 요청이 원격 DB에서 완료되는 것을 되돌리는 기능은 아닙니다.
- 네트워크 단절 중 새로 시작된 세션은 만료될 수 있으므로 서버 쪽 수명 제한과 추후 재확인 UX가 필요합니다.
- 실제 Supabase·Google OAuth·2기기 환경에서 요청 지연, 로그아웃, 세션 만료를 반드시 추가 검증해야 합니다.
- 실제 광고 완료 검증이 없으므로 정식 보상 지급 기능은 미활성화 상태를 유지합니다.

기존 운영 DB·메인 브랜치·공개 사이트를 변경하지 않았습니다.
