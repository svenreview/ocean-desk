# Ocean Desk 2.0 — 계정별 컬렉션 표시·로컬 데모 분리

**상태:** Draft PR / 개발 코드 작성, 임시 CI 검증 통과. 실제 Supabase 인증 및 운영 배포 미진행.

## UI 데이터 원칙
- 비로그인/서버 인증 미설정: 기존 `od-mvp-local-rewards-v1`의 로컬 데모 퍼즐·티켓·보유 공간을 보여줌.
- Supabase Auth로 로그인하여 서버 조회가 성공하면 `od:server-collection` 스냅샷으로 서버 퍼즐·여행 티켓·소유 공간을 표시.
- 로그인 사용자 컬렉션은 **읽기 전용**이며, 세계지도 지역 추첨·퍼즐 데모 적립 버튼을 비활성화함.
- 로컬 데모 데이터는 서버 컬렉션으로 합치거나 자동 이전하지 않으며, 서버 데이터도 브라우저 데모 저장소에 쓰지 않음.
- 로그아웃하면 메모리에 있던 서버 컬렉션을 폐기하고 기존 로컬 데모 상태로 복귀.
- 비동기 서버 조회에 세대 번호를 두어 로그아웃/계정 변경 전의 오래된 결과가 다시 표시되는 것을 방지.
- 기본 무료 환경과 정식 계정은 UI에 각각 **로컬 데모 / 서버 계정**으로 표시.

## 개인별 서버 데이터
- `od_wallets`: `pieces`, `tickets`; 사용자 ID별 지갑.
- `od_owned_environments`: 계정이 가진 공간 ID. 누구에게나 기본 제공되는 발리 오션카페·산토리니 오션테라스는 별도 포함.
- `od_focus_attempts`: 사용자별 집중 기록 최근 10건 읽기 전용.
- 접근 권한: Supabase RLS로 소유자만 조회 가능. 서버 검증 보상·티켓 추첨은 브라우저에서 직접 변경 불가.

## 자동 테스트
- `tests/ocean-desk.spec.mjs`: 가상의 계정별 컬렉션 스냅샷을 주입하여 서버 보유 공간의 해금, 로컬 비보유 공간 잠금, 추첨 버튼 차단, 로그아웃 시 로컬 데모 복귀, 로컬 저장 내용 불변을 검사.
- GitHub Actions Chromium 브라우저 테스트 **8/8 성공**.
- 별도 임시 PostgreSQL 서버 거래 및 RLS 통합 테스트 성공.

## 아직 완료되지 않은 부분
- 실제 Google Cloud OAuth 설정, Supabase Provider 활성화, 실제 로그인 및 기기간 동기화 종단 간 테스트.
- 운영 Supabase 테이블/Edge Functions 배포 미진행; 서버 실제 스냅샷 조회는 아직 실환경 확인하지 않음.
- 실제 서버 티켓 사용 및 광고 검증 보상 연동 미구현.
- 로컬 데모 보상과 서버 계정 보상을 혼동하지 않도록 정식 출시 시 가이드 강화 필요.
- 서버 지갑이 없는 계정은 초기화 기능 실행 후 재조회. 현재 UI는 초기화 버튼을 제공하지만 자동 생성은 미구현.

장기 확장: OCEAN → MOUNTAIN → NATURE. 동일 사용자 ID 기반 컬렉션 유지.
